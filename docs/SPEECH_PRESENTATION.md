# 声音与数字人表达

## 两条独立时间线

`ConversationState` 描述对话生成过程；`SpeechPlaybackSnapshot` 描述输出设备正在播放的语音。模型生成结束不等于扬声器已经播完，桌面表现层会优先使用实际播放状态。

Rust 原生播放器先解码 WAV 并计算约 40 毫秒窗口的 PCM 能量包络，再根据 Rodio 播放进度选择口型值。左右声道分别平方计算，避免反相立体声被误认为静音。低能量背景噪声不张嘴，口型值限制在 0–1000。

播放开始、进度更新和结束通过 `speech_playback` 事件传递；服务快照保留最新播放状态，客户端断线后可以重新读取。事件总线将序号分配、快照更新、历史追加和广播串行化，避免音频线程与对话线程产生乱序事件。

## 当前行为

- 内置 2D 伙伴和光球使用实际播放能量。仅生成文字、TTS 未启用或播放器未运行时，不产生模拟口型。
- 外形工作室 `--preview` 继续使用明确标注的示意动画，方便离线设计。
- 对话已经生成完毕时，“打断”仍会取消剩余语音；重复打断可以安全执行。
- 断线、事件缺口、停止和故障时，表现层抑制过时口型。
- 解码后的 PCM 有样本数量上限，异常音频不会无限扩大内存占用。格式错误和已取消音频不会发出播放开始事件。

## 启用与验证

配置好 `[tts]` 和参考音频后，服务需要启用原生播放：

```powershell
cargo run -p ai-ex-service --features native-playback -- --config config/ai-ex.local.toml
```

确定性测试覆盖静音/有声区间、反相立体声、异常样本、播放结束后的状态和并发事件顺序。设备测试默认忽略，可显式运行；它只播放程序生成的静音，不采集麦克风：

```powershell
cargo test -p ai-ex-audio --all-features native_silent_playback_reports_progress_completion_and_interruption -- --ignored --nocapture
```

当前是振幅驱动，不是音素/口形识别；设备缓冲与控制轮询仍会引入延迟。VTS 适配器目前仍使用原有舞台口型命令，尚未接入这条高频播放时间线。VTS 同步、语音期间的表情延续、字幕对齐和自然过渡仍是下一阶段工作，不能据此宣称所有载体都已完成声音同步。
