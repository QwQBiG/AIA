# 整体验收流程

适用基线：0.4.0-alpha.1。先完成下面的界面体验，遇到问题再展开深度检查。没有准备对应外部服务的项目记为“未测”。

## 先用起来：无需命令行

完整解压便携包，双击 `AIex.exe`。不要在压缩包里直接运行，也不要只取出一个 EXE。欢迎页显示版本号。

| 顺序 | 你需要做什么 | 应该看到什么 |
| --- | --- | --- |
| 1 | 点击“先体验外形” | 直接出现伙伴，无需账号、模型或其他软件 |
| 2 | 查看人物立绘、切换隐藏，调整颜色、情绪和状态 | 人物的头发、五官和衣服清晰；配色与表情立即改变；窗口仍能正常操作 |
| 3 | 在预览底部点击“开始对话” | 未配置模型时打开连接设置；无需关闭并重新打开程序 |
| 4 | 选择你已有的模型服务，填写信息，保留自动启动服务并保存 | 主界面连接成功；模型可用时可以回答 |
| 5 | 输入中文，Enter 换行，Ctrl+Enter 或“发送”提交；再让它写长一点并点击“打断回复” | 输入法确认不会误发；旧回答可停止，新问题仍能继续回答 |
| 6 | 新建自己的角色，修改称呼、语气，预览后确认应用；再换外形 | 当前角色按确认结果切换，换外形不改变角色身份 |
| 7 | 保存一个场景组合，再载入并确认；设置为启动组合 | 角色与外形一起恢复；未确认时不会改变当前组合 |
| 8 | 关闭并重新打开程序，再进入对话 | 本机收藏与已设置的启动组合能恢复；云端密钥可能需要重新填写 |

聊天页以人物与消息为主；角色、场景、设置从顶部切换。把窗口缩小到最小尺寸，输入框与发送按钮仍应可用。在“设置与诊断”进入“连接设置”或“首页”，有未保存草稿时应先提示。原来的光球场景会显示人物，再保存后使用新外形标识，角色身份不变。

若看到未送达提示，检查恢复到输入框的文字；输入框已有新草稿时，从“查看保留的消息”恢复或复制。连接超时的文字会标为“结果待核对”，不会自动放回输入框；先检查服务是否已经回答，再决定恢复，避免重复发送。

第 1、2 步完全离线。第 4 步起需要你自己的模型服务：云端密钥，或已经启动并装有模型的 Ollama / KoboldCpp。程序包不包含模型。

本版先测试外形、文字和角色即可；语音与麦克风默认关闭，准备好资源后再测试。不需要先安装 VTube Studio。

反馈只需写：**第几步、点击了什么、实际看到什么、期望什么**。启动错误窗口可复制错误信息；需要日志时查看程序目录下的 `data/logs/service.log`，分享前去掉个人对话或凭据。

便携模式使用 `data/ai-ex.local.toml`，默认端口 17878；下面源码深度检查使用另一份配置和端口。两种流程不必一起执行。角色收藏仍有本机共享设置，请给测试角色加“验收”前缀。

## 0. 准备与版本确认

以下命令都在仓库根目录的 PowerShell 中执行。先关闭本项目的旧测试窗口，保存手头工作；只停止你明确识别的测试服务。

```powershell
git rev-parse --short HEAD
cargo build -p ai-ex-service --all-features --locked
cargo build --manifest-path crates/ai-ex-desktop/Cargo.toml --locked
```

两次构建都应成功。记录提交号、Windows 版本、模型后端/模型名。本文用明确的 debug 程序路径；`AIex-Desktop.cmd` 会优先运行已有 release 程序，可能不是刚构建的版本。桌面目录若有旧的旁置服务程序，请先同步更新。

准备独立测试配置，已有文件保留：

```powershell
if (-not (Test-Path -LiteralPath 'target/manual-test')) {
    New-Item -ItemType Directory -Path 'target/manual-test' | Out-Null
}
if (-not (Test-Path -LiteralPath 'target/manual-test/ai-ex.local.toml')) {
    Copy-Item -LiteralPath 'config/ai-ex.acceptance.example.toml' -Destination 'target/manual-test/ai-ex.local.toml'
}
```

测试配置使用 `127.0.0.1:7879`，与默认日常端口 7878 分开；记忆和令牌位于 `target/manual-test/`，此目录不进入 Git。首次设置会创建令牌。端口被占用时先确认占用的是哪份服务，必要时修改测试配置的 `control.bind`，不要复用无法识别的服务。

角色收藏与部分外形偏好仍属于本机共享桌面设置，测试名称统一加“验收”前缀，不清空整个收藏。`target` 属于构建目录，保留测试证据前不要执行 `cargo clean`。

## 1. 无需模型：外形预览

```powershell
& .\crates\ai-ex-desktop\target\debug\ai-ex-desktop.exe --preview
```

| 编号 | 操作 | 通过条件 |
| --- | --- | --- |
| A1 | 切换人物立绘和隐藏外形，调整颜色和减少动态效果 | 立即显示对应效果；隐藏后没有残留身体；减少动态效果后停止呼吸与眨眼动画 |
| A2 | 切换预览状态和情绪，缩放窗口 | 界面可操作，主要内容可达，无崩溃；预览动作明确属于示意 |
| A3 | 关闭后重新打开预览 | 成功保存的外形偏好可恢复；正式桌面偏好与预览各自保存 |

生成一份测试图片包（目标目录必须不存在；重复测试可直接复用已生成包）：

```powershell
cargo run --manifest-path crates/ai-ex-desktop/Cargo.toml --example create_image_pack -- target/manual-test/image-character
```

在预览里选择“图片角色”，导入 `target/manual-test/image-character`，检查状态图片与缩放。再输入一个不存在的包路径并导入：应报错且保留已加载的图片。完成后关闭预览。

## 2. 文字对话与错误恢复

准备一个可用的模型服务；样例使用 Ollama，但可在设置中改成你实际使用的后端和模型。

```powershell
& .\crates\ai-ex-desktop\target\debug\ai-ex-desktop.exe --config target/manual-test/ai-ex.local.toml --setup --developer
```

向导中填写模型信息，保留自动启动服务，保存并进入桌面。先不启用 TTS、麦克风、VTS、OBS 或直播。已有云端配置重开时，需再次提供配置指定的密钥环境变量，或通过设置填写当前进程使用的密钥。

| 编号 | 操作 | 通过条件 |
| --- | --- | --- |
| B1 | 保存设置并等待连接 | 连接成功，当前模型状态可查；配置与令牌生成在测试目录 |
| B2 | 输入“请用两句话介绍你自己”，再连续追问两轮 | 回答可见，交互能继续；只生成文字时原生外形不假装持续张嘴 |
| B3 | 请求较长回答，在思考/生成时点击“打断”，随后发送短问题 | 旧回答停止继续生成；新问题可正常回答，没有混入旧回合尾句 |
| B4 | 重复点击“打断”，之后再次提问 | 界面保持可用，下一轮能完成；无永久“忙碌”状态 |
| B5 | 在测试配置中改为不可达的模型地址，重启该测试服务后提问 | 明确显示连接/模型错误；修复配置并重启后能恢复 |

更改 TOML 前关闭对应托管桌面；重新打开时沿用上面的 `--config` 路径，日常重开无需 `--setup`。若复用独立服务，必须重启那份服务才能加载修改。模型自身很快时，可多试几次较长回答来覆盖 B3 的等待阶段。

## 3. 角色身份、收藏与记忆

先确认测试配置中 `memory.enabled = true`，并记录两个角色的档案 ID。

| 编号 | 操作 | 通过条件 |
| --- | --- | --- |
| C1 | 在“角色收藏”新建“验收 A”，编辑语气并收藏；载入草稿 | 草稿可编辑；尚未确认应用时，当前服务角色不变化 |
| C2 | 点击“预览并请求确认”，先取消一次，再确认应用 | 取消保留原角色；成功应答后才显示新角色正在使用 |
| C3 | 告诉 A“我的验收暗号是青禾-7391”，等回复完成；换图片外形或调整人物配色后再询问 | 档案 ID 不变；换身体不会清空此角色记忆 |
| C4 | 将 A“复制为独立角色”得到“验收 B”，确认 ID 不同并应用；询问原暗号 | B 不应取得 A 的记忆；切回 A 后可继续使用 A 的经历 |
| C5 | 编辑同一身份，增加版本后收藏；尝试以同一 ID/版本收藏不同设定 | 新版本可保存；冲突版本被拒绝，旧收藏保留 |
| C6 | 移出一个测试收藏，再“撤销移出” | 列表记录可恢复；移出不删除服务记忆 |

模型回答有随机性，“答对暗号”不能单独证明持久化与隔离。可检查测试 JSONL 的身份分布（只输出 ID 与条数）：

```powershell
Get-Content -LiteralPath 'target/manual-test/memory.jsonl' -Encoding UTF8 |
    ForEach-Object { $_ | ConvertFrom-Json } |
    Group-Object profile_id | Select-Object Name, Count
```

完整回答应留下有效记录。生成途中取消的回合不保存；回答已经完整并开始落盘后才打断，记录仍会保存，这是预期行为。

## 4. 场景保存、资源与启动恢复

| 编号 | 操作 | 通过条件 |
| --- | --- | --- |
| D1 | 载入 `config/scenes/quiet`，查看预览后取消；再载入并确认 | 取消不改变当前组合；确认后角色与外形一起切换 |
| D2 | 应用“验收 A”和测试图片包；另改人格草稿但不应用；保存到尚不存在的 `target/manual-test/scene-a` | 导出使用已应用的 A；未应用草稿不进入包，图片随包保存 |
| D3 | 再向同一目标保存；导入一份清单中引用了缺图的测试副本 | 已有目录拒绝覆盖；损坏候选包被拒绝，当前有效外形保留 |
| D4 | 将导出场景副本移到另一个测试目录，重新载入 | 能靠包内资源加载，不依赖最初生成图片的位置 |
| D5 | 载入导出场景后“将当前组合设为启动组合”，关闭并重开同一测试配置 | 桌面新启动服务时恢复 A 和对应外形；输入在恢复完成前不会发给错误角色 |
| D6 | 询问 A 的暗号，查看收藏和外形 | 重开后记忆与已保存偏好仍可用；不继续播放关闭前的旧语音 |

场景保存要求目标目录不存在、上级目录已经存在。启动组合记录当前快照；后续临时编辑不会自动更新它。涉及移动或损坏资源的测试只操作测试副本。

## 5. 服务所有权与重新连接

1. 关闭自动启动服务的测试桌面，确认该测试服务退出。只核对测试端口或你启动的进程，不按名称批量结束进程。
2. 在一个终端独立启动服务：

```powershell
& .\target\debug\ai-ex-service.exe --config target/manual-test/ai-ex.local.toml --serve
```

3. 另一个终端从仓库根目录打开客户端：

```powershell
& .\crates\ai-ex-desktop\target\debug\ai-ex-desktop.exe --config target/manual-test/ai-ex.local.toml --connect-only --developer
```

4. 应能连接已有服务；如有启动组合，应先预览确认。关闭此桌面后，独立服务应仍运行。
5. 再次连接，在服务终端按 Ctrl+C 关闭并重新启动该测试服务：桌面应提示断线并恢复连接，不继续显示旧回合口型。终端退出与重连时间需记录实际结果。
6. 在桌面触发“急停”，验证后续受保护请求被拒绝；急停后需重启测试服务恢复。结束本组测试时关闭测试客户端和独立服务。

## 6. 可选：真实声音与插话

此部分由你准备好设备后操作。先保持麦克风关闭，单独验证播放。关闭测试服务，在测试 TOML 中补全已有 `[tts]` 段（不要重复添加同名段）：

```toml
[tts]
enabled = true
base_url = "http://127.0.0.1:9880"
ref_audio_path = "D:/你的音色目录/reference.wav"
prompt_text = "填写参考音频中真实说出的文字"
text_lang = "zh"
prompt_lang = "zh"
```

启动已配置模型与音色的 GPT-SoVITS 服务，再以测试配置重开桌面。参考音频必须能被合成服务访问；上面的路径是占位示例，需要替换。

| 编号 | 操作 | 通过条件 |
| --- | --- | --- |
| E1 | 请求短回答并等待播完 | 能听见语音；字幕按当前句显示；静音时嘴部回落 |
| E2 | 请求多句回答，观察模型生成结束后的朗读 | 仍在播放的字幕、情绪和口型继续跟随该句；不因生成完成提前消失 |
| E3 | 分别在合成等待、播放中、文字生成完但声音未完时打断 | 剩余旧语音停止；立即提问可播放新回答，无旧声音插回 |
| E4 | 重复同一句回答两次，连续做几轮对话/打断 | 两句均能正常播放；旧进度不会重新激活已经取消的句子 |
| E5 | 停掉测试 TTS 服务后提问，再恢复并继续 | 故障可诊断，程序不崩溃；恢复后新一轮可播放 |

记录从点击打断到实际停止的时间，以及是否有设备残留缓冲声音。250 毫秒是单次适配器等待上限，不是设备实测延迟指标。

播放测试通过后，配置实际 Whisper 兼容转写接口，在原有 `[duplex]` 段设置 `enabled = true`，补充以下子段并重启：

```toml
[duplex.asr]
endpoint = "http://127.0.0.1:8000/v1/audio/transcriptions"
model = "whisper-1"
language = "zh"
```

使用耳机测试说话、停顿、背景噪声及朗读中插话，记录转写准确度、误触发与抢话效果；先通过点击打断，再区分麦克风/VAD、转写和运行时问题。采集关闭后不应继续接受麦克风输入；修改开关需重启服务。

## 7. 可选：VTS、OBS、直播与更长会话

- VTS：按实际应用配置接口和表情热键，验证连接、动作及断线后的文字对话。恢复应用后再发起对话，观察诊断。原生外形仍可独立使用。
- OBS：配置 WebSocket 凭据环境变量和实际字幕输入源，验证字幕、断线与重连。当前生成动作不等于播放同步，不把词级口型作为通过条件。
- 直播：[Bilibili 连接说明](BILIBILI_CONNECTOR.md)。先使用建议模式验证事件，再由你决定是否测试自动回应。
- 连续使用：保留一个固定角色和场景运行多轮，记录响应时间、资源占用趋势、重复回复、身份连续性和退出结果。偶发模型表现问题与可复现程序故障分别记录。

## 8. 自动检查与结果记录

需要重新确认代码基线时执行；任一步失败先保存错误，不继续当作“全部通过”：

```powershell
cargo fmt --all -- --check
cargo fmt --manifest-path crates/ai-ex-desktop/Cargo.toml -- --check
pwsh -NoProfile -File tools/check_architecture.ps1
cargo test --workspace --all-features --locked
cargo test --manifest-path crates/ai-ex-desktop/Cargo.toml --locked
cargo clippy --workspace --all-targets --all-features --locked -- -D warnings
cargo clippy --manifest-path crates/ai-ex-desktop/Cargo.toml --all-targets --locked -- -D warnings
```

真实设备测试默认忽略；这些自动检查不会替你完成上面的窗口与声音验收。Windows GNU 构建需要兼容的完整 MinGW-w64 导入库；不要用系统 DLL 目录代替导入库。构建成功后还需检查实际程序的启动与退出，保留原始错误用于判断工具链问题。

发现问题时，在“开发者诊断”使用“导出日志”；文件写到启动目录的 `aiex-desktop-diagnostics.log`。同时保存测试服务终端的相关错误与触发时间。日志可能含对话文本，分享前检查内容，不附带密钥或控制令牌。

复制下面的记录，每个问题写一份；正常结果可仅登记编号和“通过/失败/未测”：

```text
提交号 / Windows 版本：
测试编号（例如 E3）：
结果：通过 / 失败 / 未测
模型后端 / 模型名 / 启用的可选组件：
实际操作（从启动方式开始）：
预期现象：
实际现象 / 是否每次复现：
触发时间 / 打断延迟：
相关日志或截图位置：
```

先完成 A–D 和服务生命周期测试，再提交第一轮反馈。语音、直播或外形插件未准备时明确标注未测；不需要为了填满表格一次启用所有组件。
