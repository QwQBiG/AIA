# 0.3.0-alpha.1 · 对话与恢复 Alpha

发布日期：2026-09-07。此版本是本轮阶段交付点，上传 GitHub 后停止开发，等待用户恢复任务。

延续上一版的角色收藏、身份记忆、原生伙伴/光球/图片外形与场景组合，这一版重点让数字伙伴在等待、拥堵和插件故障时仍能让出话轮，并继续下一次对话。核心实现继续使用 Rust。

## 这一版的变化

- **等待时也能打断**：取消覆盖模型请求初始化、记忆检索、流式生成、语音队列等待和末尾未带标点的句子。被取消的未完成回答不会写入记忆，也不会混入下一轮上下文。
- **先停声音，再清理外形**：语音取消与字幕、表情等可选输出分离。舞台清理会尝试所有匹配适配器，一个适配器卡住不会阻止其他适配器收到停止请求。
- **外形故障可降级和恢复**：外形调用有等待上限；失败后本轮跳过后续字幕、表情和张嘴动作，文本与语音仍能继续。清理阶段重试，诊断事件记录不可用与恢复状态。
- **停止期间保护记忆**：完整回答进入持久写入后，打断会取消声音，同时等待写入结束。关闭也遵循这个边界，避免为了退出而丢弃正在落盘的记录。
- **拥堵有明确边界**：等待对话有容量上限，超出时返回可重试错误；重复停止请求可合并，控制通道不会因自身排队而卡死。
- **统一默认格式**：使用标准 `cargo fmt`，移除 README 的旧格式规范与自定义格式检查脚本，更新持续检查。

## 使用与升级

需要 Rust 1.96，同时构建服务与桌面：

```powershell
cargo build -p ai-ex-service --all-features --locked
cargo build --manifest-path crates/ai-ex-desktop/Cargo.toml --locked
```

Windows 用户构建后可双击 `AIex-Desktop.cmd`。已有角色、图片和场景保持 schema v1，不需要迁移；本机配置与私人记忆仍保留。模型、GPT-SoVITS 服务及音色资源需要另外配置。

日常使用流程不变：选择角色和外形，开始对话；等待回答或朗读过程中使用“打断”，之后可以继续输入。外形异常可以在开发者诊断中查看 `avatar-output` 的状态变化。

详细操作参见[桌面指南](../DESKTOP_USER_GUIDE.md)、[声音与表达](../SPEECH_PRESENTATION.md)、[角色收藏](../CHARACTER_LIBRARY.md)和[场景组合](../SCENE_PACKS.md)。

## 保证的边界

- 单个输出/取消适配器的异步等待上限为 250 毫秒，这不是扬声器停止的实测延迟或整个关闭过程的硬实时保证。事件发布、操作系统调度及设备缓冲仍会影响响应。
- 活动回合的打断确认表示控制已被接收；语音取消失败会产生故障事件。适配器需要支持取消安全的异步操作；同步阻塞代码不能由异步超时强制中断。
- 已开始的持久写入不会因打断被撤销，完成的回答仍会保存。永久失去响应的存储会拖延最终关闭；I/O 失败会返回错误，当前没有崩溃恢复事务日志。
- 舞台按 `Speech` 能力分组取消。扩展作者应将可能缓慢的外形输出与语音执行器分开；同时声明语音与外形能力的单个执行器属于语音组。
- 原生字幕和外形仍跟随实际播放；VTS/OBS 继续按生成时的舞台动作调度。网页、VRM、词级字幕、音素口型和声音/行为包编辑仍在后续路线中。
- 完整首次设置点击流程、真实模型与设备、跨机器迁移仍需实机验收。本次 GitHub 交付为源码分支与版本标记，没有新增安装程序。
